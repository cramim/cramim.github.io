### 1.3 מיקום הפופאפ — ✅ בוצע (2026-08-10, שלב 0)

התיקון הזה כבר נעשה, והוא מתועד כאן כי הסיבה שלו התבררה כשונה לגמרי ממה
שנרשם קודם.

**מה חשבנו:** תקלה עתיקה ב-`app.css` — הכרטיס המוגדל `position: absolute` בתוך
`#main_box` שהוא `overflow-y: auto`, ולכן נגלל עם הרשימה.

**מה זה היה באמת:** `activity-circle-badge` הוסיף
`.v2_circle_on .activity_box { position: relative }`. מול `app.css:1128`
(`.activity_box.box_maximized`) זו **אותה specificity** — ו-`v2.css` נטען אחרי,
ולכן `relative` ניצח, הכרטיס המוגדל נשאר בזרימת המסמך, והפופאפ נפתח במיקום
הכרטיס שנלחץ. כלומר: תקלה שאנחנו הכנסנו, לא תקלה ותיקה.

הכלל המקורי (`absolute`) מעולם לא היה שבור: תיבת ההכלה שלו היא `.parent`
(`app.css:59`, `position:absolute`), שיושבת **מחוץ** ל-`#main_box` ולכן אינה
נגללת. נבדק — `absolute` נשאר יציב בכל מיקום גלילה.

**מה נעשה בפועל:**

1. `app.css:1128` — `position: fixed` ו-`margin: 0`. לא תיקון באג אלא הקשחה:
   `absolute` עבד רק במקרה, כי `.parent` מקרית מפוזישנת. מי שיוסיף אי פעם
   `position` ל-`#main_box` היה מחזיר את התקלה. `margin: 0` מתקן היסט אמיתי של
   ~14px, כי `top:50%` ממקם את קצה ה-margin.
2. `v2.css` — `position: relative` מוגבל ל-`:not(.box_maximized)`. **זה התיקון
   האמיתי.**

⚠️ **הלקח, וזה חוזר בסעיף 4.7:** `v2.css` נטען אחרי `app.css`, ולכן כל כלל
ב-v2 באותה specificity **דורס בשקט**. שני מקרים כאלה כבר נמצאו, שניהם
מ-`activity-circle-badge` ושניהם על אותו אלמנט: `position` ו-`height` של
התיאור. לפני מיזוג מלא (מסלול ג) צריך לסרוק את כל הכללים המשותפים.

## 2. ההחלטה שצריך לקבל לפני הכול

`app/v2.js` מכיל **שתי שכבות שונות שהתערבבו**:

| שכבה | מה בה | שייך לייצור? |
|---|---|---|
| **פיצ'רים** | מנוע הניסויים + עשרת השינויים | ✅ כן |
| **תשתית דף בדיקות** | מפתח כניסה, חסימת כתיבה, ניתוב `v2↔v2-mobile`, תג צף, מסך חסימה | ❌ לא |

שלוש דרכים, לפי סדר ההמלצה:

### א. פיצול לשני קבצים ← **מומלץ**

```
app/v2.js        →  מנוע + פיצ'רים            נטען ע"י כל ארבעת הדפים
app/v2-test.js   →  מפתח, read_only, ניתוב, תג   נטען רק ע"י v2.html / v2-mobile.html
```

הייצור מקבל את הפיצ'רים בלבד. דפי הווריאנט ממשיכים לעבוד ונשארים **נתיב הבדיקות
לסבב הבא** — בלי לבנות מחדש מפתח כניסה וחסימת כתיבה בעוד חודשיים.

### ב. מחיקה

מוחקים את התשתית ואת `v2.html` / `v2-mobile.html`. הכי נקי כתוצאה סופית, אבל
**מוותרים על יכולת ה-A/B**. אם יש כוונה לסבב שני — טעות.

### ג. מיזוג מלא לתוך `app.js` / `app.css`

התוצאה הנקייה ביותר, אבל דיפ ענק בלי בדיקות, ו-`v2.css` אחד משרת שני דפים כך
שפיצול ל-`app.css` + `mobile.css` מכפיל כללים. **לא עכשיו** — ראה 4.7, שמסביר
למה `activity-circle-badge` מסבך את זה במיוחד. אפשר בהדרגה, פיצ'ר-פיצ'ר, אחרי
שהשינויים חיים ויציבים.

### שלב 2 — מה בדיוק נעשה

**`index.html`** — אחרי `<script src="app/app.js"></script>`:

```html
<link rel="stylesheet" href="app/v2.css">
<script src="app/v2.js"></script>

```

**`mobile.html`** — אחרי `<script src="app/mobile.js"></script>`, **חייב להיות אחרון**:

```html
<link rel="stylesheet" href="app/v2.css">
<script src="app/v2.js"></script>
```
```html
<body class="select_disabled v2 v2_mobile">
```

**`mobile.html:51-52`** — ⚠️ בנוסף, להחליף את שתי שורות הלשוניות בגרסה מ-`v2-mobile.html:55-56`:
הלשונית `tab_activity` **ראשונה** (כלומר ימנית ב-RTL) והכיתוב שלה `בחירת פעילויות`.
בלי זה הלשונית תיפתח נכון אבל תשב במקום הלא נכון ועם השם הישן.

⚠️ **לא להעתיק** את `<title>דף בדיקות · …</title>` ואת `<meta name="robots" content="noindex, nofollow">`.

הסדר קריטי: `v2.css` אחרי `app.css`/`mobile.css`, ו-`v2.js` אחרי `app.js`/`mobile.js`.
זה מה שגורם לדריסה לעבוד בלי `!important` — ו-`activity-circle-badge` תלוי בזה
ממש (ראה 4.7).

## 4. מה חייב להיסגר לפני ההעברה

### 4.1 `grade-quota` — ✅ הוכרע (2026-08-09)

`Code.gs` פרוס, `grade_counts` מגיע מהשרת, הפיצ'ר עובר דלוק.

שתי מגבלות שנשארות נכונות ואינן חוסמות:

- **המכסה היא `floor(max/6)`.** פעילות עם מקסימום 10 → מקסימום שכבה 1.
- **אין אכיפה בשרת.** שני הורים במקביל יעברו שניהם. הנחיה, לא אכיפה.

באימות: לוודא ששכבה שהמשפחה **כבר** רשומה אליה אינה נעולה.

### 4.2 `category-home` — ✅ הוכרע (2026-08-09)

הסתרת `#filter_box_wrapper` ו-`#ico_filter` במסך הקטגוריות היא התנהגות מכוונת.
אין איסוף מדדים במערכת, ולכן המשוב יהיה איכותני בלבד.

### 4.3 `last-year-category` — קריאת שרת נוספת

מוסיף `load` שני עם הקמפיין הקודם, **בכל טעינת עמוד של כל הורה**. בייצור, בשיא
ההרשמה, זו הכפלה של העומס על ה-Apps Script, שחונק לפי מכסות. רצה ברקע עם
`please_wait` מנוטרל — לא תחסום מסך — אבל צורכת מכסה.

### 4.7 `activity-circle-badge` — הפיצ'ר היחיד שנוגע בפריסה משותפת — ⚠️ חדש

הרצועה היא `position: absolute` בתחתית הכרטיס, והיא **תלויה בכך שיש לכרטיס מקום
פנוי למטה**. במהלך הפיתוח התברר שצריך לפנות לה מקום בשלושה מצבים נפרדים:

| מצב | מאיפה המקום |
|---|---|
| כרטיס רגיל בדסקטופ | חינם — `min-height:15.5em` (`app.css:417`) חל על תיבת ה**תוכן**, ולכן פינוי מ-`.activity_box_toolbox` padding-top (16px→8px) ומ-`.activity_box_desc` (4.1em→3.6em) לא מגדיל את הכרטיס בכלל |
| מובייל | `padding-bottom: 1.6em` — אין `min-height`, אין מה לפנות |
| הפופאפ המוגדל | `padding-bottom: 2.1em` — התיאור גדל ל-`auto` (`app.css:1147`), הכרטיס גבוה מ-`min-height`, והמקום נעלם |

**מה זה אומר להעברה:**

1. הפיצ'ר דורס שני כללי פריסה משותפים (`.activity_box_desc` גובה,
   `.activity_box_toolbox` padding-top) שאינם שלו. במסלול א זה בסדר — הם
   דריסות. במסלול ג, המיקום של הרצועה והמקום שהיא צורכת **חייבים לעבור יחד**,
   אחרת התקלה חוזרת.
2. **שתי דריסות שקטות באותה specificity** — שתיהן של הפיצ'ר הזה, שתיהן על
   הכרטיס המוגדל, ושתיהן נמצאו רק אחרי שנשברו:
   - `position: relative` מול `app.css:1128` → הפופאפ נפתח במקום הלא נכון (1.3)
   - `height: 3.6em` של התיאור מול `app.css:1147` → התיאור נשאר מכווץ בפופאפ

   שתיהן מגודרות היום ב-`:not(.box_maximized)`. ה-`:not()` קיים **רק** בגלל סדר
   הטעינה. אם הכללים אי פעם יעברו ל-`app.css`, צריך לבדוק אותם מחדש — שם
   סדר הטעינה כבר לא יגן.
3. אם יתגלה מצב כרטיס רביעי — לבדוק אותו לפני שמניחים שהוא בסדר.

### 4.8 `filter-pills` — מרווח הלוגו — ⚠️ חדש

`app.css:507` נותן ל-`.filter_box` ריפוד התחלה של 15em. זה לא קישוט: `#header_logo`
הוא `position:absolute; right:4em; width:10em` (`app.css:357`) בתוך header דביק,
ולכן הוא גולש מטה על שורת הפילטרים הראשונה. `filter-pills` מחליף את ה-padding
בקיצור דרך ולכן **מצהיר מחדש** על המרווח כ-`--v2-filter-gutter: 15em`.

מי שיערוך את ה-padding של `.filter_box` בעתיד — משני הצדדים — יחזיר את החפיפה.

### 4.9 `mobile-default-tab` — למה זה wrapper ולא עריכה — ⚠️ חדש

לשונית ברירת המחדל נקבעת ב-`mobile.js:195`, ו-`mobile.js` **משותף** ל-`mobile.html`
ול-`v2-mobile.html`. לכן הניסוי עוטף את `change_tab`/`change_page` ומנתב את
הקריאה הראשונה בלבד, במקום לערוך את הקובץ.

בייצור אפשר להשאיר את העטיפה כמו שהיא — היא עובדת ומגודרת ב-`?off=`. פישוט
לעריכה ישירה של `mobile.js` אפשרי אבל **לא נדרש**, והוא מוותר על מתג הכיבוי.

### 4.10 מלכודת ה-binding המוקדם — ⚠️ חדש, כללי

`app.js:861` קושר את `app.filter` כ-handler **לאובייקט הפונקציה כפי שהיה ב-init**,
ו-`app.js:948` מריץ את `app.start` לפני שלב ה-`apply` של v2. המשמעות:
`v2.after("filter", ...)` **לא תופס** את המסלול הזה, כי הוא מחזיק את הגרסה
הלא-עטופה.

זה כבר נשך פעם אחת (`category-home`, תוקן ע"י listener מואצל על
`#filter_box_wrapper`). כל ניסוי עתידי שיעטוף פונקציה ש-`init_buttons` קושרת
ישירות ייפול באותו אופן. `v2.js:22` כבר מזהיר על אותו דפוס לגבי `app.start`.

התיקון השורשי — `.change(function(){ app.filter(); })` ב-`app.js:861` — זהה
התנהגותית לייצור, ואפשר לעשות אותו בהעברה או להשאיר.

## 6. גיבוי ונקודת חזרה

### 6.1 ⚠️ לא לגבות בתוך הריפו

GitHub Pages מגיש את **כל** מה שבריפו. `index.html.bak` או `parents/backup/`
יהיו כתובות ציבוריות שאפשר להוריד — כולל גרסה ישנה של האתר שממשיכה לרוץ מול
אותו Apps Script. תיקייה בשם `_backup` אמנם לא תפורסם, אבל רק כי Jekyll מדלג
כברירת מחדל על שמות שמתחילים ב-`_`, ואין כאן `_config.yml` ואין `.nojekyll`
שיקבעו את זה במפורש. תלות שברירית מדי בשביל רשת ביטחון.

### 6.2 נקודת החזרה היא תגית git

הגיבוי הנכון כאן הוא הריפו עצמו. לפני שנוגעים בדף הייצור:

```bash
git tag -a pre-v2-promotion -m "מצב האתר החי לפני העברת שינויי הווריאנט"
git push origin pre-v2-promotion
```

התגית מקבעת את המצב הידוע-טוב בלי להוסיף קובץ אחד לאתר.

### 6.3 שלוש דרכי חזרה, מהמהירה למדויקת

```bash
# א. ביטול ההעברה כולה — המסלול הרגיל
git revert <commit ההעברה> && git push

# ב. שחזור קובץ בודד למצב שלפני
git checkout pre-v2-promotion -- parents/index.html
git commit -m "revert index.html to pre-promotion state" && git push

# ג. השוואה: מה בדיוק השתנה מאז
git diff pre-v2-promotion -- parents/
```

מסלול ב' הוא הסיבה שהתגית שווה יותר מעותקי קבצים: אפשר להחזיר בדיוק את
`mobile.html` בלי לגעת בשאר ההעברה.

### 6.4 מה שאין לו דרך חזרה מהירה

`?v2=off` ו-`?off=<id>` מכבים פר-URL בלי פריסה — אבל **לא את שינוי הלשוניות
ב-`mobile.html`**, שהוא markup ולא ניסוי. אין מתג כיבוי גלובלי בלי פריסה.
