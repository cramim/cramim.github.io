## 2. ההחלטה שצריך לקבל לפני הכול

`app/v2.js` מכיל **שתי שכבות שונות שהתערבבו**:

| שכבה | מה בה | שייך לייצור? |
|---|---|---|
| **פיצ'רים** | מנוע הניסויים + שבעת השינויים (סעיפים 3–5, 8, ו-EXPERIMENTS) | ✅ כן |
| **תשתית דף בדיקות** | מפתח כניסה, חסימת כתיבה, ניתוב `v2↔v2-mobile`, תג צף, מסך חסימה (סעיפים 0–1, 2b, 2c, 6, 6b) | ❌ לא |

שלוש דרכים, לפי סדר ההמלצה:

### א. פיצול לשני קבצים ← **מומלץ**

```
app/v2.js        →  מנוע + פיצ'רים            נטען ע"י כל ארבעת הדפים
app/v2-test.js   →  מפתח, read_only, ניתוב, תג   נטען רק ע"י v2.html / v2-mobile.html
```

הייצור מקבל את הפיצ'רים בלבד. דפי הווריאנט ממשיכים לעבוד כמו היום ונשארים
**נתיב הבדיקות לסבב הבא** — בלי לבנות מחדש מפתח כניסה וחסימת כתיבה בעוד חודשיים.
עלות: פיצול קובץ אחד לשניים.

### ב. מחיקה

מוחקים את התשתית מ-`v2.js`, מוחקים את `v2.html` / `v2-mobile.html`. הכי נקי
כתוצאה סופית, אבל **מוותרים על יכולת ה-A/B**. אם יש כוונה לסבב שני — זו טעות.

### ג. מיזוג מלא לתוך `app.js` / `app.css`

מפרקים כל ניסוי ומטמיעים אותו במקור. התוצאה הנקייה ביותר, אבל:
- דיפ ענק על קבצים בני 48KB בלי שום בדיקות
- `v2.css` הוא קובץ אחד שמשרת שני דפים; פיצול ל-`app.css` + `mobile.css` מכפיל כללים
- הפיצ'רים מסתמכים על סדר טעינה ועל hooks; המרה לקוד ישיר היא כתיבה מחדש, לא העתקה
- ביטול = חזרה על כל העבודה, במקום להסיר שתי שורות

**לא כדאי עכשיו.** אפשר לעשות את זה בהדרגה, פיצ'ר-פיצ'ר, אחרי שהשינויים כבר חיים ויציבים.

### שלב 2 — שלוש שורות בכל דף ייצור

ב-`index.html`, אחרי `<script src="app/app.js"></script>`:

```html
<link rel="stylesheet" href="app/v2.css">
<script src="app/v2.js"></script>
```
```html
<body class="v2 v2_desktop">
```

ב-`mobile.html`, אחרי `<script src="app/mobile.js"></script>` — **חייב להיות אחרון**:

```html
<link rel="stylesheet" href="app/v2.css">
<script src="app/v2.js"></script>
```
```html
<body class="select_disabled v2 v2_mobile">
```

⚠️ **לא להעתיק** את `<title>דף בדיקות · …</title>` ואת `<meta name="robots" content="noindex, nofollow">`.

הסדר קריטי: `v2.css` אחרי `app.css`/`mobile.css`, ו-`v2.js` אחרי `app.js`/`mobile.js`.
זה מה שגורם לדריסה לעבוד בלי `!important`.

## 4. מה חייב להיסגר לפני ההעברה

### 4.1 `grade-quota` — ✅ הוכרע (2026-08-09)

השינוי ב-`Code.gs` פרוס ועובד. `grade_counts` מגיע מהשרת, הפיצ'ר **עובר דלוק**
(`on: true`).

שתי מגבלות שנשארות נכונות ואינן חוסמות:

- **המכסה היא `floor(max/6)`.** פעילות עם מקסימום 10 → מקסימום שכבה 1.
  אם החלוקה השווה לא מתאימה לחלק מהפעילויות, הפתרון הוא עמודת מכסה-לשכבה בגיליון.
  שינוי שרת נפרד, לא חלק מההעברה הזו.
- **אין אכיפה בשרת.** הבדיקה כולה בדפדפן: שני הורים שנרשמים במקביל יעברו שניהם.
  זו הנחיה, לא אכיפה. אם המכסה חייבת להיות מובטחת — נדרשת בדיקה ב-`save` בשרת.

בזמן האימות (סעיף 5) יש לוודא במיוחד ששכבה שהמשפחה **כבר** רשומה אליה אינה נעולה
— `own_grades()` מחסירה את ההרשמה של המשפחה עצמה, וזה הנתיב שהכי כדאי לראות חי.

### 4.2 `category-home` — ✅ הוכרע (2026-08-09)

הסתרת `#filter_box_wrapper` ו-`#ico_filter` במסך הקטגוריות היא **התנהגות מכוונת
ומבוקשת**. עובר דלוק.

נותר נכון: אין איסוף מדדים במערכת (AB-TESTING.md סעיף 7), ולכן המשוב יהיה איכותני
בלבד.

### 4.3 `last-year-category` — קריאת שרת נוספת

מוסיף `load` שני עם הקמפיין הקודם, **בכל טעינת עמוד של כל הורה**. היום זה קורה
לקבוצת בדיקה קטנה. בייצור, בשיא ההרשמה, זו הכפלה של העומס על ה-Apps Script.

Apps Script חונק לפי מכסות. בהינתן שכבר היו בעיות רשת מהמובייל בפרויקטים אחרים,
כדאי לוודא שהקריאה הזאת לא מתחרה בקריאה הראשית. היא רצה ברקע עם `please_wait`
מנוטרל — כלומר לא תחסום מסך — אבל היא כן צורכת מכסה.

### 4.4 עטיפת `window.swal` הגלובלית

`grade-quota` עוטף את `window.swal` בשביל כל הדף. בייצור זה חל על כל דיאלוג
שהאפליקציה פותחת. העטיפה מעתיקה את המאפיינים הסטטיים
(`Object.keys(_swal).forEach`) — עבד בבדיקות, אבל שווה מבט נוסף לפני ייצור,
במיוחד ב-`swal.fire` ובשרשראות `.then`.

### 4.5 מספר הוואטסאפ

`login-whatsapp` מקודד קשיח את `972549959886`. לאמת שזה המספר הנכון והפעיל —
זה הדבר הראשון שמשפחה חדשה תראה.

### 4.6 כפילות ה-HTML

אחרי ההעברה, `v2.html` ו-`index.html` מתחילים להיפרד שוב. אין build step.
מי ששומר את דפי הווריאנט מקבל על עצמו `diff index.html v2.html` בכל שינוי מבני.

- [ ] `index.html` בדסקטופ: מסך הקטגוריות עולה, לחיצה נכנסת, "כל הקטגוריות" חוזר
- [ ] `index.html` במובייל אמיתי: **מגיע ל-`mobile.html`**, לא נתקע (זה מה ששומר הניתוב היה משבש)

- [ ] **הרשמה אמיתית נשמרת בגיליון** — זו הבדיקה שמוכיחה ש-`read_only` ירד
- [ ] החלפת קמפיין מהתפריט → נשארים ב-`index.html`/`mobile.html`, לא נזרקים ל-`v2.html`
- [ ] אין תג צף, אין מסך "דף בדיקות", `index.html` בלי `?key=` נטען רגיל
- [ ] דיאלוג השכבות: תוויות מוצגות, ושכבה שכבר נרשמנו אליה **אינה** נעולה
- [ ] `?off=grade-quota` מכבה את הנעילה — מוודא שמתג הכיבוי שרד
- [ ] console נקי מ-`[v2] … failed`

## 6. ביטול

`git revert` על commit ההעברה ו-push. הפריסה יוצאת לדרך אוטומטית.

מחזיר `"build_type": "legacy"`, ו-`Deploy Pages` (`.github/workflows/pages.yml`)

commit היא `gh api -X POST repos/cramim/cramim.github.io/pages/builds`.

כדי להפעיל את ה-workflow באמת צריך שני צעדים בהגדרות הריפו — להעביר את
Pages ל-Build and deployment → **GitHub Actions**, ולהפעיל את ה-workflow המושבת.

בלי פריסה** — ה-revert הוא המסלול, ולכן כדאי שההעברה תהיה commit אחד ונקי.
